## Editable operating manuals
Status: IMPLEMENTED

Commands:
- `/ownermanual` — Owner read/edit/add
- `/adminmanual` — Owner read/edit/add, Sudo Admin read-only

Manual browsing uses one Telegram pager message with Previous/Next, page indicator, Owner-only Edit/Add controls and Close. New sections are appended automatically; internal keys/order are generated by the bot. Migration 0010 plus runtime normalization correct legacy literal `\\n` sequences.

Manual storage remains isolated from FAQ matching and AI grounding.

## Multiuser / Staff Inbox isolation
Different Telegram users are independent across profile/language, question logs, conversation mode, claimant, topic, and AI/human lifecycle.

Migration 0008 prevents same-user concurrent first-message duplicate topic creation with a D1 provisioning lock. Staff-side delivery fails closed if an isolated topic cannot be established; it must not mix users in the Staff Inbox main chat.

## Production go-live prerequisites
Before running the production workflow:
- create the separate production D1 database
- save its UUID as `CLOUDFLARE_PRODUCTION_D1_DATABASE_ID`
- configure production Worker runtime secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `BOT_OWNER_TELEGRAM_ID`, `AI_CONFIG_MASTER_KEY`
- deliberately initialize required production D1 operational content/config
- keep the Telegram webhook on the current known-good endpoint until production health is green

After production health passes, move the Telegram webhook to the production Worker and perform smoke tests.
